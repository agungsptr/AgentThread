# AgentThread `agt guide` and Generated Skill (Plan 9) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Agents can look up how to use `agt` for their role at any time, from one vendor-neutral source that always matches the installed version.
- `agt guide <role>` prints a full guide for the main, coordinator or worker role.
- `agt init`, `agt setup` and `agt start` write a generated skill `.claude/skills/agt/SKILL.md` from the same source, in the project root and in every thread worktree.
- The skill is kept out of git and can be turned off.

**Architecture:**
- **One pure function** builds the guide text from the config and the role prompts.
- **The CLI** prints that text.
- **A skill writer** wraps the same text in SKILL.md frontmatter. It writes the file wherever AGENTS.md is written, and in the project root. Exclusion reuses the existing per-worktree exclude mechanism.
- **The role prompts** gain one line pointing to `agt guide`. This also covers a non-Claude main that loses its role after compaction.

**Tech Stack:** TypeScript on Bun ≥ 1.1.34, `bun:test`.

**Spec:** `docs/specs/2026-10-09-agentthread-design.md` §11–§12. Context: the user chose "an optional skill generated from the same source" (conversation, 2026-10-31).

## Global Constraints

- Bun ≥ 1.1.34 and TypeScript `strict: true`. Run tests as `env -u HERDR_ENV -u HERDR_WORKSPACE_ID -u HERDR_TAB_ID -u HERDR_PANE_ID -u AGT_HERDR_IT bun test`. Run the full suite under `timeout 300`, plus `bun run typecheck`, before every commit.
- Never run the real `herdr`, `claude`, `opencode`, `codex` or `omp` binaries, or `agt start`, outside tests. Leave no `agt daemon run`, `agt __spawn` or `agt-e2e-*` processes behind.
- No `Bun.spawnSync` on daemon paths.
- Skill path, exactly: `.claude/skills/agt/SKILL.md`.
- Skill frontmatter, exactly:
  ```
  ---
  name: agt
  description: Use when working in an AgentThread project (AGT_ROLE is set, or the project has .agentthread/) — how to use the agt CLI for your role (main, coordinator or worker): threads, tickets, workers, notes, questions, handoffs and recovery.
  ---
  ```
- Config key `agents.skill: boolean`, default `true`. When it is `false`, nothing is written, and an existing generated skill is left alone.
- New role-prompt line, exactly, added as the last rule of every role (main, coordinator, worker): `- When unsure how to do something with agt, run: agt guide <role>` (with `<role>` filled in).
- The generated file starts with this line right after the frontmatter, exactly: `<!-- Generated by agt; do not edit. Regenerated by agt init, agt setup and agt start. -->`.
- Never overwrite a `.claude/skills/agt/SKILL.md` that the project tracks in git, or one that lacks the generated marker line. Leave such a file alone and log `agt: .claude/skills/agt/SKILL.md is not generated by agt; leaving it alone`.

## Review Focus

1. **No unwanted git change.** The skill never shows up in `git status`, in the main checkout or in any worktree. A coordinator commit never includes it. Tests are in Task 2.
2. **The project's own skill is safe.** A tracked or hand-written `.claude/skills/agt/SKILL.md` is never overwritten. Tests are in Task 2.

### Task 1: `agt guide <role>`

**Files:**
- Create: `src/agents/guide.ts`
- Modify: `src/cli/main.ts` (command and USAGE) and `src/agents/prompts.ts` (the new line)
- Test: `tests/agents/guide.test.ts`, `tests/cli/cli.test.ts`, `tests/agents/claude.test.ts`

**Interfaces:**
- Produces `guide(o: { role: SessionRole | "all"; root: string; config: Config; thread?: { id: string; title: string; slug: string; worktree: string } }): string`.

**Contents of the guide**, per role, as markdown:
1. **Rules.** The role's rules from `systemPrompt`, with the identity line removed. The thread is a placeholder `<thread>` when none is given.
2. **Commands.** Every `agt` command that role uses, with its exact syntax from USAGE.
   - main: `thread new`, `choose`, `cancel`, `tell`.
   - coordinator: thread status, ticket add/reopen, worker spawn, decide, note, progress, question, answer, handoff, tell.
   - worker: ticket claim/done/block, note, progress, question.
3. **When things go wrong.**
   - A HANDOFF REQUEST: write the handoff with `agt handoff <thread> --stdin`, then stop.
   - A CHECKPOINT reminder: run `agt progress`.
   - A worker question: answer it with `agt answer`.
   - A blocked worker: check it or replace it.
   - A ticket left `in_progress` with no worker: reopen it and spawn a worker.
   - "never push; never commit as a worker; never bypass the commit guard".
4. **Where state lives:** the thread directory under `.agentthread/` (brief.md, sub.thread.md, board.md).

`role: "all"` concatenates the three role guides under `## Main`, `## Coordinator` and `## Worker`.

`agt guide` with no role uses `$AGT_ROLE` when it is set. Otherwise it prints `all`. An unknown role gives a usage error (exit 2). The command never contacts the daemon.

- [ ] **Step 1: Write the failing tests.**
  - The guide for each role contains its command lines verbatim from USAGE.
  - The guide contains each role's rules.
  - `all` has the three headings.
  - `agt guide worker` prints the worker guide and exits 0, with no daemon running.
  - `agt guide nope` exits 2.
  - The new prompt line appears in all three roles, and in AGENTS.md for coordinator and worker.
- [ ] **Step 2: Run them.** Expected: FAIL.
- [ ] **Step 3: Implement.**
- [ ] **Step 4: Run the full suite and typecheck.** Commit `feat: agt guide prints the full how-to for each role`.

### Task 2: Generated skill in the project root and in every worktree

**Files:**
- Create: `src/agents/skill.ts`
- Modify:
  - `src/agents/agents-md.ts` (write the skill with the other worktree files, and exclude it)
  - `src/project/setup.ts` (`initCommand`, after setup)
  - `src/cli/main.ts` (`start` refreshes it)
  - `src/config/config.ts` (`agents.skill`)
  - `README.md` (one paragraph)
- Test: `tests/agents/skill.test.ts`, `tests/agents/agents-md.test.ts`

**Interfaces:**
- Consumes `guide({ role: "all", ... })` from Task 1.
- Produces `skillText(o: { root; config }): string`, which is the frontmatter, the marker line and `guide(all)`.
- Produces `writeSkill(dir: string, o: { root; config; tracked: boolean; log }): "written" | "unchanged" | "skipped"`.

**Behavior:**
- **Project root.** `agt init`, `agt setup` and `agt start` write `<root>/.claude/skills/agt/SKILL.md`. They hide it with `/.claude/skills/agt/` in the main repository's `.git/info/exclude`, the common dir, which also covers worktrees. They add that line only when the path is not tracked.
- **Worktrees.** `writeAgentsFiles` and `writeAgentsFilesAsync` write the same file into the worktree, through the same hide step as AGENTS.md.
- **Leave alone.** A tracked file, or a file without the marker line, is skipped with the exact log line. If the project tracks the file, it is already in the worktree, and that copy is skipped too.
- **Turned off.** With `agents.skill: false`, nothing is written.
- **Rewrites.** A file is rewritten only when its content differs.
- **Daemon paths.** These use the async runner, with no spawnSync.

- [ ] **Step 1: Write the failing tests:**
  - init writes the root skill. Its content starts with the frontmatter and the marker, and it contains `## Coordinator`.
  - `git status --porcelain` in the root shows nothing new.
  - A thread worktree gets the skill, and its `git status --porcelain` is clean.
  - A coordinator `git add -A && git commit` in the worktree does not include the skill.
  - A tracked `.claude/skills/agt/SKILL.md` is left alone, with the log line.
  - A hand-written untracked file without the marker is left alone, with the log line.
  - With `agents.skill: false`, nothing is written.
  - Running twice gives `unchanged`.
- [ ] **Step 2: Run them.** Expected: FAIL.
- [ ] **Step 3: Implement.**
  - README: under "Notes on instruction files", add the generated skill:
    - where it lives;
    - that it is regenerated by init, setup and start;
    - that it is kept out of git;
    - that `agents.skill: false` turns it off;
    - which agents read `.claude/skills` (Claude Code, and omp, which reads `.claude` rules and skills).
- [ ] **Step 4: Run the full suite and typecheck.** Commit `feat: agt writes a generated agt skill in the project and its worktrees`.
